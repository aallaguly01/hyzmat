Ты — Senior Full-Stack разработчик и архитектор. Твоя задача — спроектировать и разработать MVP Telegram Mini App (TMA) для P2P-маркетплейса услуг.

МЕТОДОЛОГИЯ РАЗРАБОТКИ (СТРОГО):
Ты должен использовать подход Spec-Driven Development (SDD) и Test-Driven Development (TDD), а также стандарт OpenSpec.
Работаем по следующим шагам:

1. Создание спецификаций: Сначала сгенерируй файлы архитектуры (например, `spec.md` или `architecture.md` в формате OpenSpec), описывающие модели данных, API-контракты и UI-состояния. Дождись моего аппрува спецификации, прежде чем писать код.
2. TDD: Напиши падающие тесты (unit-тесты для бизнес-логики и интеграционные/компонентные тесты для UI) до реализации функционала.
3. Реализация: Напиши код, который заставит тесты пройти.
4. Современные стандарты: Настрой линтеры, git hooks (husky/lefthook, если применимо к стеку) и подготовь конфигурацию для CI/CD.

ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ (БИЗНЕС-ЛОГИКА):
Приложение состоит строго из 2-х услуг и 2-х вкладок в нижней панели навигации (Bottom Tabs).

Вкладка 1: «Лента» (Просмотр)

- Содержит переключатель фильтра: «Почта» / «Перевод» + строку поиска по городу.
- Карточка услуги «Почта»: Откуда (Город) ➔ Куда (Город), Дата вылета.
- Карточка услуги «Перевод»: Откуда (Город отдачи денег) ➔ Куда (Город получения денег), Сумма + Валюта (всегда доллар $).
- На каждой карточке есть кнопка «Написать». По клику должен открываться чат с создателем заявки (через t.me/username или методы Telegram API).

Вкладка 2: «Мои заявки» (Управление)

- Содержит список заявок, созданных текущим пользователем.
- На каждой карточке есть кнопка «Удалить».
- Содержит акцентную кнопку «+ Создать заявку» (Floating Action Button или фиксированная кнопка).
- есть возможность редактировать

Флоу создания заявки:

1. Выбор типа: Почта или Перевод.
2. Если «Почта»: поля "Откуда" (текст), "Куда" (текст), "Дата" (date picker).
3. Если «Перевод»: поля "Город, где отдаю деньги", "Город, где получат деньги", "Сумма" (number), "Условия/Комиссия" (number/текст).
4. АВТОРИЗАЦИЯ: Пользователь не вводит свой ник. Приложение должно использовать метод Telegram Web Apps API `window.Telegram.WebApp.initDataUnsafe.user` для автоматического извлечения `username` (или ID) пользователя при создании заявки. Внизу формы нужно отобразить: "Ваш Telegram для связи: @{username}".
5. Нативная кнопка `MainButton` Telegram Web API с текстом "Опубликовать".

ТЕХНИЧЕСКИЕ ТРЕБОВАНИЯ:

- Использовать нативные цвета Telegram (Telegram Web Apps API CSS variables), чтобы поддерживать светлую/темную темы автоматически.
- UI должен быть легким, быстрым и отзывчивым.
- Обработка сценариев, когда у пользователя не установлен @username (использовать fallback на first_name + tg://user?id=).

ТВОЙ ПЕРВЫЙ ШАГ:
Проанализируй требования и создай OpenSpec файл проекта с описанием структуры БД, API и компонентов UI. Преждлжи стэк и выведи его мне на проверку.
