# feed-ui Specification

## Purpose
Вкладка «Лента» — просмотр актуальных заявок всех пользователей с фильтром по типу и поиском по городу, и быстрый переход в чат с автором.

## Layout
```
┌──────────────────────────────┐
│ [ Почта | Перевод ]          │  ← SegmentedControl (sticky)
│ 🔍 Поиск по городу      [×]  │  ← SearchInput (sticky)
├──────────────────────────────┤
│ ┌──────────────────────────┐ │
│ │ Ашхабад ➔ Москва         │ │  ← MailCard
│ │ ✈ 15 окт 2026            │ │
│ │ @ivan          [Написать]│ │
│ └──────────────────────────┘ │
│ ┌──────────────────────────┐ │
│ │ Ашхабад ➔ Стамбул        │ │  ← TransferCard
│ │ $1 500 · Комиссия 2%     │ │
│ │ Иван           [Написать]│ │
│ └──────────────────────────┘ │
├──────────────────────────────┤
│   📰 Лента  │  📋 Мои заявки  │  ← BottomTabs
└──────────────────────────────┘
```

## Components
| Компонент | Props | Назначение |
|---|---|---|
| `BottomTabs` | `active: "feed" \| "my"` | Навигация между `/feed` и `/my`, фиксирована снизу с учётом `safe-area-inset-bottom` |
| `SegmentedControl` | `value, options, onChange` | Переключатель типа |
| `SearchInput` | `value, onChange, placeholder` | Поле поиска с кнопкой очистки |
| `ListingCard` | `listing, actions` | Базовая карточка; рендерит `MailCardBody` или `TransferCardBody` по `type` |
| `ContactButton` | `contact` | Кнопка «Написать» |
| `FeedList` | `type, city` | Список + состояния + infinite scroll |
| `EmptyState`, `ErrorState`, `CardSkeleton` | — | Состояния |

## UI State Machine (`FeedList`)
```
idle → loading ─┬─ success(items>0) ─ loadingMore → success | errorMore
                ├─ empty
                └─ error ─(retry)→ loading
```

## Requirements

### Requirement: Навигация по вкладкам
Приложение SHALL иметь ровно две вкладки в нижней панели: «Лента» (`/feed`, по умолчанию) и «Мои заявки» (`/my`). Нижняя панель MUST скрываться на экранах формы.

#### Scenario: Старт приложения
- **WHEN** пользователь открывает Mini App
- **THEN** активна вкладка «Лента», выбран тип «Почта», строка поиска пуста

#### Scenario: Переключение вкладки
- **WHEN** пользователь нажимает «Мои заявки»
- **THEN** открывается `/my`, вкладка подсвечена цветом `--tg-theme-button-color`, срабатывает `HapticFeedback.selectionChanged()`

### Requirement: Фильтр по типу
Переключатель SHALL содержать два значения «Почта» (MAIL) и «Перевод» (TRANSFER); выбранное значение сохраняется при переходе между вкладками (в памяти сессии).

#### Scenario: Переключение на «Перевод»
- **WHEN** пользователь выбирает «Перевод»
- **THEN** выполняется запрос `GET /api/listings?type=TRANSFER` (с текущим `city`), отображаются только карточки переводов

#### Scenario: Возврат на вкладку
- **WHEN** пользователь выбрал «Перевод», ушёл в «Мои заявки» и вернулся
- **THEN** по-прежнему выбран «Перевод», данные показываются из кэша без мигания skeleton

### Requirement: Поиск по городу
Строка поиска SHALL фильтровать ленту по подстроке в городе отправления или назначения; запрос отправляется с debounce 300 мс.

#### Scenario: Ввод запроса
- **WHEN** пользователь вводит «моск»
- **THEN** через 300 мс после последнего ввода выполняется `GET /api/listings?type=<текущий>&city=моск`
- **AND** промежуточные значения не порождают отдельных запросов

#### Scenario: Очистка
- **WHEN** пользователь нажимает «×»
- **THEN** поле очищается и загружается лента без параметра `city`

#### Scenario: Ничего не найдено
- **WHEN** по запросу нет заявок
- **THEN** показывается `EmptyState` «По запросу „моск“ ничего не найдено»

### Requirement: Карточка «Почта»
Карточка MAIL SHALL отображать «{fromCity} ➔ {toCity}», дату вылета в формате `d MMM yyyy` на русском (например «15 окт 2026»), подпись автора (`contact.label`) и кнопку «Написать».

#### Scenario: Рендер карточки
- **WHEN** получена заявка `{ type: "MAIL", fromCity: "Ашхабад", toCity: "Москва", departureDate: "2026-10-15" }`
- **THEN** видно «Ашхабад ➔ Москва» и «15 окт 2026»

### Requirement: Карточка «Перевод»
Карточка TRANSFER SHALL отображать «{fromCity} ➔ {toCity}», сумму в формате `$1 500` (без копеек, если они нулевые; иначе `$1 500.50`), условия (если есть) и кнопку «Написать».

#### Scenario: Рендер суммы
- **WHEN** `amount = "1500.00"`
- **THEN** отображается «$1 500»
- **WHEN** `amount = "99.50"`
- **THEN** отображается «$99.50»

#### Scenario: Без условий
- **WHEN** `conditions` отсутствует
- **THEN** строка условий не рендерится

### Requirement: Кнопка «Написать»
Кнопка SHALL открывать чат с автором согласно `contact` (см. `telegram-auth` → «Построение контакта автора»). Для своих заявок (`isOwn = true`) кнопка MUST NOT отображаться, вместо неё — метка «Ваша заявка».

#### Scenario: Автор с username
- **WHEN** пользователь нажимает «Написать» на карточке с `contact.kind = "username"`
- **THEN** вызывается `WebApp.openTelegramLink("https://t.me/ivan")`

#### Scenario: Своя заявка
- **WHEN** карточка имеет `isOwn = true`
- **THEN** кнопки «Написать» нет, есть метка «Ваша заявка»

### Requirement: Состояния загрузки
Лента SHALL показывать skeleton при первой загрузке, `EmptyState` при пустом результате, `ErrorState` с кнопкой «Повторить» при ошибке, и подгружать следующую страницу при прокрутке к концу списка.

#### Scenario: Первая загрузка
- **WHEN** данные ещё не получены
- **THEN** отображаются 3 `CardSkeleton`

#### Scenario: Пустая лента
- **WHEN** API вернул `items: []` без фильтра по городу
- **THEN** «Пока нет заявок. Создайте первую!» с кнопкой, ведущей на `/listings/new`

#### Scenario: Ошибка сети
- **WHEN** запрос завершился ошибкой
- **THEN** показывается `ErrorState` с текстом ошибки и кнопкой «Повторить»; нажатие повторяет запрос

#### Scenario: Бесконечная прокрутка
- **WHEN** пользователь долистал до последней карточки и `nextCursor != null`
- **THEN** запрашивается следующая страница с `cursor`, внизу показывается индикатор загрузки
- **WHEN** `nextCursor = null`
- **THEN** дальнейших запросов нет

#### Scenario: Pull-to-refresh / возврат в приложение
- **WHEN** пользователь возвращается в приложение (событие `visibilitychange` → visible) спустя > 60 с
- **THEN** лента перезапрашивается в фоне без skeleton

### Requirement: Комментарий в карточке
Карточка заявки обоих типов (в ленте и в «Моих заявках») SHALL показывать `comment`, если он есть, отдельным блоком под основной информацией; переносы строк сохраняются.

#### Scenario: Карточка с комментарием
- **WHEN** получена заявка с `comment = "WhatsApp +99365000000"`
- **THEN** в карточке видно «WhatsApp +99365000000»

#### Scenario: Без комментария
- **WHEN** `comment = null`
- **THEN** блок комментария не рендерится
